# Architecture, roles and delivery entry

The former proposal and large candidate roster have been superseded by the unified owner review. Current decisions and task order are maintained only in [index.html](index.html); agent exports are generated from its contract.

- [Engineering contract](engineering-contract.md): package/version/identity, Domain/Data/Presentation/App boundaries, scene/app lifetime, committed writes, migrations, candidate/speech interfaces and widget publication.
- [Delivery plan](delivery-plan.md): explicit P0/P1 ordering, owners, dependencies and acceptance.
- [Agent context](agent-context.md): minimal read path, authority and regeneration commands.
- [Source audit](audit/report.md): measured inventory, corrections and open evidence gaps.

Use docs and automated checks before installing custom agents. No custom-agent configuration is added in this audit. A content reviewer and an iOS integration reviewer may be useful for recurring bounded reviews when delegation is explicitly requested. They share the same contracts; neither adds product authority or establishes independent human certification.

Search matching/order, favorites ordering, alphabet group UX and all 49 DS-U decisions are already recorded. Do not treat older discovery questions as unresolved current requirements. Kana teaching data and the candidate dependency bank still require authoring; a resolved UX decision does not make those datasets complete. Dedicated Accessibility acceptance is deferred; Dynamic Type/RTL/native-state work remains current.
