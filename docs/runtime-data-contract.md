## Serialized formats

Manifest v1 fields are `schemaVersion`, `contentVersion`, `generatorVersion`, `mode`, `sourceInputHashes`, `authoredLanguages`, `requiredLanguages`, `releaseBlockers`, `orderedLessons`, `entities`, `shards`, `unitMilestones`, `candidateIndexVersion`, `speechIndexVersion`, `searchIndexVersion` and `searchIndex`. Content version is derived from canonical input/validator/generator hashes. An entity maps its UUID to kind, root UUID, target UUID, level, optional source number, shard and JSON pointer. A shard contains `schemaVersion`, `rootID` and runtime `content`; the pointer is local to that version, never saved as identity. The original UUID is the only persisted identity. Each file pin contains SHA-256 and byte count; search also includes its relative path.

SQLite `user_version=1` contains `metadata(key,value)`, `results(id,targetID,rootID,kind,authoredOrder)` and `fields(resultID,locale,original,normalized)` with a locale/normalized lookup index. Metadata binds content/normalization versions. Every searchable vocabulary, grammar, pattern, example, dialogue, Kanji and contextual Kanji word has a stable result and parent/target route. Localized meaning/explanation fields resolve requested-language missing values to English before indexing; Japanese/kana/romaji/Han-Viet are common fields. The reader checks the result inventory against manifest identities. Queries are read-only and bounded, optionally lesson-scoped, with group order then exact/prefix/contains and authored-order/UUID ties. Lookup folds width/case, Latin accents including đ, and Katakana to Hiragana while preserving dakuten. Display fields remain original. T03 supplies UI grouping/materialization, debounce, IME and stale-session handling; the synchronous query seam does not claim those features.

User state v1 persists only schema/content versions, monotonic revision, optional level and shared language (nil means System), appearance, furigana, independent per-level endpoint UUIDs and direct favorites with type/UUID/committed timestamp. A favorite whose ID is absent or wrong-kind in the current package remains persisted and resolves as unavailable; it is removable but cannot be added through a new write. The Favorites surface may display that row, while search and widget eligible pools include only targets resolving to the exact saved kind. It never persists a reader route, scroll position, search session or derived parent expansion. `StateWriter` is one app-scoped actor over a single `StatePersistence`. `SwiftDataStatePersistence` uses one local, non-CloudKit model record containing the versioned snapshot; curriculum entities are never imported. A save atomically replaces one snapshot and rolls its model context back on failure. Do not create a second app writer/context for the same store.

## Transactions and upgrade gate

An action validates against the current revision, validates its next state, saves, then exposes the committed snapshot. An explicit in-flight gate prevents actor reentrancy from interleaving writes across async persistence/publication. No-op actions do not advance revision. Favorite timestamps are taken through the clock seam; equal times sort by target UUID. Parent and child favorites stay direct and independent.

A prefix plan captures level, target lesson UUID, operation, exact changed UUIDs and revision. Multiple changed lessons require confirmation; a single changed lesson commits directly. Discarding/canceling a plan makes no write. Any intervening revision returns a recomputed `reviewAgain` plan; even a previously confirmed range cannot silently apply the new range. N4 has no synthetic lesson 0/25 and never implies N5 knowledge.

`StatePublication` is a committed-state seam for T06, called only after successful saves. Publication failure returns a committed state with `publicationPending=true`; retry publishes the current revision without another state write. App/widget composition must rebuild publication from saved state on startup by calling `retryPublication`; T06 owns atomic shared-container projections, stale-producer ordering and WidgetKit. The seam/fake publisher tests are not a native widget implementation.

`UpgradeMapping` schema v2 binds exact old/new content versions, an optional owner approval reference and explicit one-to-one same-level `lessonReplacements`. Validate both immutable packages first. Existing IDs whose identity metadata changes under the same UUID are rejected. Content IDs may be removed; saved favorites keep the old ID and become unavailable. Lesson reordering/removal/replacement may be adopted only when each currently learned lesson maps by unchanged ID or an explicit reviewed replacement and that mapped set exactly equals a prefix in the new order. If a learned lesson has no mapping, the mapped set is not contiguous, or adoption would mark any additional lesson, return `migrationRequiresDecision` before saving. With no learned prefix, no lesson-state mapping is necessary. Lesson mappings never redirect favorites. A successful migration commits state once before switching repositories; failure restores the old manifest/state and leaves the old package/store usable. There is no text-based equivalence or automatic rollback to an older content version. Unsupported saved state fails without resetting it.
